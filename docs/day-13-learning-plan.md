Day 12 已有來源國／地區排名表與月度趨勢圖，今天在此基礎上補足指標解讀與展示。展示範圍固定為美國月度進口、`8542／H6`、202301～202412 的已發布資料；不把歷史展示範圍誤稱為最新可取得的貿易月份。Day 11 真實資料的國家覆蓋率為 63.01%～82.92%，24 個月的 HHI 均不可對外顯示。畫面須清楚解釋這個限制，不能以 0、內部 `hhi_raw` 或假設值代替。

## 1. 固定圖表口徑與資料可用性

**預計時間：25～35 分鐘。**

- [x] 查核正式 mart 的 `period_start_date`、`partner_code`、`partner_type`、`map_iso3`、`primary_value`、`world_value`、`yoy`、`country_coverage`、`hhi`、`hhi_status`、`published_at`，以及品質摘要的最新檢查與發布欄位。
- [x] 確認 24 個月份的發布狀態、YoY 非空筆數、HHI 狀態分布與地圖碼涵蓋率；保存查詢時間及 job ID，據此決定視覺元素。
- [x] 沿用 Day 12 的固定資料表允許清單、參數化查詢、月份分區條件、查詢處理量上限與快取清除方式。所有圖表只讀已發布資料。
- [x] 數值金額仍以 BigQuery `NUMERIC` 核對；轉為浮點數的圖表只供視覺顯示。`NULL` 保留為資料不足，不補為 0。

| 主題 | 展示口徑 |
|---|---|
| 來源國／地區 | 只取 `partner_type='country'`；特殊代碼 490 可供對帳，但不列入國家排名、地圖或 HHI |
| World | 每月只取一次；不可將夥伴列中重複的 `world_value`、`country_coverage` 或 `hhi` 直接加總 |
| YoY | 同夥伴、同商品與分類的本月對去年同月；無有效去年基期時顯示「無可比較基期」 |
| HHI | 僅 `hhi_status='ok'` 且 `hhi` 非空時畫數值；其他狀態顯示原因與同月國家覆蓋率 |
| 新鮮度 | 分開顯示資料涵蓋的最新月份、正式表最後發布時間、最近品質檢查／發布嘗試時間與畫面讀取時間 |

## 2. 補齊來源國圖表與 YoY

**預計時間：60～75 分鐘。**

以現有 Top N 排名資料製作可讀的金額長條圖；標示期間、美元單位、排序與 Partner 篩選。圖表與排名表共用同一組查詢結果，避免兩種圖表採不同集合或分母。Top N 只控制顯示筆數；占期間 World 的比例仍以選定期間每月 World 金額合計為分母。

YoY 至少提供一個可核對的逐月呈現方式：單一來源國／地區的 YoY，或 World 月度 YoY。若加入多 Partner 合計的 YoY，須先為本月與去年同月選定相同、可比較的夥伴集合，分別加總金額後計算比率；不得加總或平均各列 `yoy`。多個夥伴缺去年基期時，顯示可比較集合及排除筆數，或不提供合計成長率。2023 年因展示範圍沒有 2022 年基期，不補 0，也不拿前一筆代替去年同月。

畫面將 `0.25` 顯示為 `25%`，並保留負成長的負號；說明 YoY 是金額變化，不能直接推論進口數量、實際產能或供應鏈韌性。切換日期或 Partner 後，圖表與文字必須一起更新；空資料顯示明確提示。

## 3. 呈現 HHI、國家覆蓋與資料新鮮度

**預計時間：55～70 分鐘。**

新增按月的國家覆蓋率與 HHI 狀態摘要。覆蓋率以已確認國家金額／World 金額計算；呈現為百分比，並與 HHI 的可用性分開。當 `hhi_status='insufficient_coverage'` 時，標示「覆蓋不足，HHI 不顯示」，保留實際覆蓋率及適用門檻的說明。若資料集中沒有可顯示 HHI 的月份，使用狀態表或說明卡，避免畫一條全為 0 的趨勢線。品質 `PASS` 表示發布門檻通過，不表示 HHI 可用。

新鮮度區塊明確區分四個時間概念：最新資料月份、最新成功正式發布時間、最新品質檢查／發布嘗試時間，以及本次畫面讀取時間。若快取仍有效，標示可能使用快取，並提供既有的重新讀取按鈕。最新嘗試若 `FAIL`，仍顯示既有正式版本的發布時間，不能將失敗嘗試寫成資料已更新。所有時間加上時區或統一轉成台北時間；資料月份與發布時間不可互換。

## 4. 評估地圖與散佈圖的資料條件

**預計時間：25～35 分鐘。**

依[總規格](trade-analytics-spec.md)的「依資料可用性加入」原則決定是否製作地圖與散佈圖，不以圖表數量代替正確性。

| 圖表 | 可以加入的條件 | 不符合時的交付 |
|---|---|---|
| 地圖 | 已發布資料的 `map_iso3` 有可用映射，且所用地圖元件能正確辨識；統計未映射國家／地區的筆數與金額 | 改用排名長條圖，列出映射缺口與限制；不把 490 或未知代碼硬套國家位置 |
| 散佈圖 | X／Y 軸都有明確業務意義、同一觀測 grain 與足夠的非空值；標示單位、篩選與缺值排除數 | 不製作散佈圖，改以表格或趨勢顯示相同資訊，記錄不可用原因 |

若採用金額與 YoY 散佈圖，每個點須對應明確的 `月份 × 國家／地區`，且 YoY 有有效去年同月基期；不可將期間合計金額與單月 YoY 混作同一筆觀測。地圖或散佈圖不能繞過 Day 12 的查詢邊界與處理量限制。

## 5. 真實資料核對與失敗情境

**預計時間：45～60 分鐘。**

選一組固定條件，例如 `202401～202412／8542／H6／partner 458`，將畫面的月度金額、YoY 與來源國排名和獨立 BigQuery SQL 核對。另選 2023 年月份確認無 2022 年基期時 YoY 為空；用整段 24 個月檢查覆蓋率與 HHI 狀態。保存固定 SQL、查詢 job ID、處理量、畫面數值及驗證時間；精確金額與百分比在格式化前比對。

| 情境 | 預期結果 |
|---|---|
| 正常日期與 Partner 切換 | 長條圖、YoY、覆蓋／品質與文字解讀使用相同條件，無舊快取污染 |
| 缺去年同月或前期金額無效 | YoY 為資料不足，不顯示 0% 或無根據的增減 |
| HHI 全部不可用 | 顯示 24 個月的覆蓋／狀態與原因，不顯示 HHI 數值線或 0 |
| 地圖碼缺漏或特殊代碼 490 | 未映射量可查；490 不畫成國家點，不從其他圖表的總額中靜默刪除 |
| 已發布 PASS、最新嘗試 FAIL | 正式版本時間與最新失敗時間分開顯示；以隔離 fixture 驗證，不修改正式表 |
| 空結果、查詢權限或處理量錯誤 | 清楚顯示空狀態或錯誤；不沿用先前成功結果冒充目前篩選結果 |

測試範圍以本次新增查詢、指標計算與 Streamlit 呈現為主。真實資料沒有出現的失敗情境可使用標記清楚的 fixture，不把 fixture 數值寫成正式觀察。

## 6. 寫出 3 項分析觀察並驗收 M3

**預計時間：35～45 分鐘。**

從已發布資料選出 3 項互不重複的觀察。每項包含篩選條件、比較期間、精確數值、計算方式或 SQL、可支持的結論，以及限制。例如來源國金額排名變化、可比較月份的 YoY 變化、國家覆蓋率與 HHI 不可用的關係；實際數字只能在查詢後填入。不得用「有圖表」代替分析，也不能僅憑進口金額或 HHI 宣稱因果、產能或替代能力。

| 交付物 | 內容 |
|---|---|
| Dashboard 與查詢 | 來源國長條圖、YoY、覆蓋／HHI 狀態與新鮮度；地圖／散佈圖依資料條件決定 |
| 展示與核對證據 | 固定條件 SQL、job ID、處理量、畫面結果、反例測試與可重現啟動方式 |
| 分析說明 | 3 項有數據支持的觀察，每項列出範圍、計算口徑與限制 |
| [學習日誌](learning-log.md) | 實際日期與本人投入時間、做出的口徑決策、驗收結果及未解問題 |

完成後用自己的話回答：

1. 為什麼不能將不同來源國的 `yoy` 加總或平均後當作整體 YoY？
2. 為什麼 24 個月品質皆 `PASS`，HHI 卻仍全部不可顯示？
3. `country_coverage`、`hhi` 與 `world_value` 為何不能直接在夥伴列上相加？
4. 最新資料月份、最新成功發布時間、最新品質嘗試時間與畫面讀取時間各代表什麼？
5. 地圖缺少映射或 YoY 缺少基期時，圖表與分析敘述應如何處理？

## 擷取、續跑與倉儲

每次查詢一個商品、一個月份，合併至多十個市場；回應達到上限時拆分市場群組，單一市場仍達上限則停止，不接受可能截斷的資料。World 與來源國明細從同一回應拆分並分別驗證。

公開 Preview API 的筆數上限為 500。實測 API 額度耗盡時回傳 HTTP 403 與 `Retry-After`；程式依伺服器指定的秒數等待，其他認證失敗不視為同一類錯誤。可選的 API Key 只透過 HTTP 標頭傳送，完整 API 明確指定 `maxRecords=100000`。參考：[API 說明](https://uncomtrade.org/docs/un-comtrade-api/)、[額度](https://uncomtrade.org/docs/subscriptions/)。

本機及 S3 分區包含報告市場、HS 版本、商品、月份、資料種類及修訂版。重跑核對內容 checksum 與 manifest 識別，不覆寫已存在但內容不同的修訂版。`--revision` 可用於明確建立新修訂；既有較新修訂不降版。

S3 寫入維持不可變原檔；雲端載入以月份為交易單位。寫入前驗證來源筆數、金額、粒度與 checksum，交易內檢查既有版本，成功後才更新雲端檢查點。失敗交易回滾，可依原始檔重跑。查詢保留每月分區條件與掃描上限。

新事實表為 `fct_multi_market_ic_imports`，先按最高修訂、最新擷取時間及分類版本選定完整來源快照，再排除 World、未核對及特殊彙總來源。受影響月份使用分區替換，因此新修訂刪除的舊來源列不會殘留。月度及來源指標分別為 `mart_multi_market_ic_monthly` 與 `mart_multi_market_ic_partners`。市占分母及成長基期按相同報告市場、商品及日曆月份對應。

原有美國 8542 模型仍保留；staging 明確限定原本範圍，避免多市場原始資料混入舊指標。

## JSON v2 與前端

- 金額與比率維持精確十進位字串；缺值維持 null，不合成零值。
- 每列加入報告市場及商品，manifest 列出市場、商品與實際可用月份。
- 發布及離線讀取均驗證版本、筆數、SHA-256 與跨檔金額一致性。
- manifest 同時列出有效明細、正金額筆數與是否達到 100,000 筆門檻。未達門檻的預覽會明確標示歷史回補中。
- 前端預設美國及五類商品全選，零件獨立標示；保留四張圖與深色介面。
- 多商品圖表先合計相同範圍的分子與 World 分母，再計算市占；明細及 CSV 保留原始商品與分類版本。
- 跨市場共同比較使用實際可用月份的交集，包含期間內部的缺月。
- 離線單檔由已驗證網站 release 建立，不需改寫容器唯讀掛載的前端原始資料。

## 驗證及正式完成條件

本機執行 Python 測試、前端測試、Ruff、Mypy；Docker 使用既有 Airflow 映像、關閉網路及唯讀掛載驗證三個 DAG。BigQuery 使用 `dbt build --indirect-selection cautious`，只將本次模型及其完整依賴的測試納入建置。

`--complete-backfill` 會等待既有擷取鎖、處理剩餘批次、載入所有成功來源、建置並測試模型，再產生 JSON 與離線頁面。正式輸出另以 `--require-row-target` 阻擋少於 100,000 筆的快照；驗證失敗不替換既有有效快照。

筆數統計只能計入同一張事實表中的有效來源明細，不計 World、特殊彙總、父類、歷史副本或 dbt 各層重複資料。另報正金額筆數，不使用零值湊數。

歷史擷取完成、雲端模型測試、JSON 一致性、CSV 篩選及離線驗證全部通過，才可宣告 spec 完成。新月度 DAG 使用 auto 模式：完整歷史流程成功完成前沒有排程；成功寫入驗收狀態後，才在既有 Airflow 啟動每月排程。月度任務使用獨立狀態檔且再次檢查筆數門檻，不新增常駐服務。
